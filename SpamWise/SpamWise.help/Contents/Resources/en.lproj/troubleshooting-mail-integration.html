Troubleshooting Mail integration

Automation denied: open System Settings → Privacy & Security → Automation and allow SpamWise to control Mail. Recheck the connection. Contacts access is optional; denial leaves that evidence unknown. Do not grant Full Disk Access or disable system security protections as a workaround.

No automatic action: confirm setup is complete, SpamWise is running, pause and dry run are off, and the relevant account passed its disposable-message probe. MailKit remains dry-run-only until signed incoming callbacks, account identity, and timing are validated. Server-routed Junk is outside the automatic Inbox scan.

An Apple Mail move is confirmed only after observing the expected client mailbox and unchanged message source. The 30-second settling window is not a server acknowledgement. Ambiguous, changed, recovered, or missing messages fail safely. Inspect Mail and restore a disposable probe manually if needed; no Trash action is used.

IMAP requires explicit TLS credentials, read-only account validation, account/mailbox/UIDVALIDITY/UID identity, and discovered special-use destinations. Actions require server support for UID MOVE. Missing capabilities, changed UIDVALIDITY, or ambiguous destinations leave mail unchanged. No live IMAP acceptance is implied by offline protocol tests.

Provider unavailable: check the selected model and that provider’s Keychain credential. Apple on-device requires supported hardware and model availability. Private Cloud Compute additionally requires Apple’s managed entitlement; it is unavailable without that entitlement. OpenAI and Gemini need separate configured credentials and live verification. No provider silently falls back.

A successful build or notarization does not prove live Mail callbacks, external-provider behavior, IMAP account compatibility, calibration, or Mac App Store acceptance. Keep pending runtime checks visible and use disposable messages for acceptance tests.
