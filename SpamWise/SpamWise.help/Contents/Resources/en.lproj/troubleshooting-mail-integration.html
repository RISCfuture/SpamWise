Troubleshooting Mail integration

Automation denied: open System Settings → Privacy & Security → Automation and allow SpamWise to control Mail. Recheck the connection. Contacts denial is optional and leaves the relationship unknown.

No incoming callbacks: enable SpamWise in Mail → Settings → Extensions and check Activity. MailKit remains dry-run-only because the SDK exposes no stable account identifier and signed callback timing has not been established for this build.

No automatic action: confirm setup is complete, SpamWise is running, pause is off, dry run is off, and the relevant account passed the disposable-message probe. Use the Mail rule script to request an Inbox scan. Server-routed Junk is not automatically covered by this Inbox route.

Ambiguous or stale message: SpamWise requires exactly one match within one account and matching raw source. It leaves ambiguous matches untouched. A moved or modified message may need manual handling in Mail.

Keychain or shared storage unavailable: run a correctly signed build with the original App Group and Keychain access-group entitlements. A compiler build alone does not validate those permissions. Do not grant Full Disk Access as a workaround.

API unavailable: confirm your key and Haiku 5.5 access in Account settings. Network and rate-limit failures fail open and use bounded retries. Unsupported models never silently fall back.

Gatekeeper rejects a development test runner: cancel the Move to Trash prompt and resolve development signing/provisioning in Xcode. Do not disable system security protections. Test-runner rejection is separate from application behavior.

Acceptance still requires controlled live incoming mail, configured-account and server-Junk checks, callback-delay and cancellation probes, shared Keychain verification, and a fresh setup test. The implementation does not claim those tests ran merely because it compiles.
